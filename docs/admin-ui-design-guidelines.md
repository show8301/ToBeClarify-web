# 後台 UI 設計規範

更新日期：2026-10-16

本文件記錄清醒夢後台管理介面的共用版面基準。新增或調整後台功能頁面時，優先沿用這裡的間距規則；個別元件的內距與控制項間距可依內容另行調整，但不可取代頁面區塊之間的標準留白。

## 後台分頁功能標頭

以「訂單查詢」的英文分類、頁面標題與功能說明三層結構為共同基準，只套用 `.adminTheme .adminPageHeading`，不影響公開頁面、顧客點餐、登入／錯誤頁或面板內標題。

- 英文分類：10px、800 字重、行高 1、字距 .18em、大寫，與主標題距離 9px。
- 頁面標題：32px、850 字重、行高 1.2，字距 -.055em；桌面與手機維持一致，不再隨各頁放大到 42–60px。
- 功能說明：14px、行高 1.7，與標題距離 13px，最多 760px 寬；長文允許自然換行。
- 統一文字層級與間距，保留各頁文案、英文分類色及操作按鈕。標頭外框、分隔線及響應式操作列維持原有功能需求；不將同一個規則套用到所有 div。
- 來源集中於 `styles/admin/layers/50-modern.css`，同時涵蓋 `AdminPage` 與既有手寫 `.adminPageHeading`；新增分頁沿用此結構，不再新增個別字級覆寫。

「營運」、「營運管理」等導覽大分類使用 12px、1.2 行高及較緊字距，與功能項目形成清楚層級；相關樣式集中於 `styles/admin/layers/50-modern.css`。

## 標準行內說明：小驚嘆號

互動核心為中立的 [InlineHelp](../components/InlineHelp.tsx)，`AdminHelp` 保留後台樣式包裝。點餐等非後台畫面使用同一核心及 [共用樣式](../styles/shared/inline-help.css)，遵守下列幾何與互動規格，避免跨功能匯入後台實作。

- 補充填寫說明、規則與名詞解釋統一使用 [AdminHelp](../features/admin/shared/AdminHelp.tsx)，以圓圈驚嘆號（CircleAlert）置於標題或標籤右側，水平間距 6px、垂直置中。避免在表單下方常駐整段補充文字；載入、錯誤及操作結果仍直接顯示。
- 沿用 `iconActionButton` 的尺寸來源，行內說明以 token 設定桌面 24px 點擊區、16px 圖示，無可見外框或底色；觸控／混合輸入裝置點擊區為 44px。這是使用者確認的行內說明標準，不變更一般純圖示操作按鈕的尺寸。
- 使用 Base UI Popover，滑鼠移入 150ms、鍵盤 focus-visible 或點擊均可開啟；支援 Escape、點擊外部及浮層內「關閉」。預設朝下，透過 portal 避開容器裁切並自動處理視窗邊緣。
- 浮層包含可讀標題與說明、明暗主題及焦點外框，寬度不超過 340px 或視窗扣除 32px，可用高度不足時內部捲動。樣式集中於 [styles/admin/inline-help.css](../styles/admin/inline-help.css)，由後台樣式入口載入。
- 表單有說明圖示時，同排所有欄位標籤列保留一致高度（桌面至少 24px、觸控至少 44px），文字與圖示垂直置中、控制項上下緣對齊。圖示不放入 `<label>` 內，避免觸發欄位或混入欄位名稱。
- 點餐碼填寫／既有 UID 與臨時排班說明已共用此元件；後續新增或修改同類說明沿用此標準。

## 後台側欄品牌區：均衡齊邊

- 桌面版採左圖右文的緊湊橫排，下方另放完整寬度的「↗ 公開網站」按鈕。不新增或替換「清醒夢」、「LUCID DREAM」、按鈕文案及原 `/favicon.ico` 圖片。
- 圖片外框及右側兩行文字區塊皆為 `44px` 高；文字區使用 `26px`／`14px` 兩列及中間 `4px` 留白，與圖片區塊上下齊邊。圖片使用 contain、不裁切，維持原有品牌圖框與明暗配色。
- 中文為 `21px`、700 字重、`26px` 行高；英文為 `11px`、500 字重、`14px` 行高。沿用既有品牌字型，不透過換字型補償尺寸。
- 圖文水平間距 `12px`，品牌列與下方按鈕垂直間距 `12px`，由 grid gap 統一控制；按鈕不另加上方 margin。品牌區至下方分隔線保留 `16px` 內距。
- 公開網站按鈕為 `13px` 文字、至少 `34px` 高、`6px 12px` 內距；觸控裝置至少 `44px` 高，保留既有跳轉及鍵盤焦點。
- `1020px` 以下保留原有橫向導覽標頭、較小品牌文字與原本的網站按鈕顯示規則；`680px` 以下沿用英文隱藏規則，不將桌面雙列高度硬套至手機。
- 實作集中於 `styles/admin/layers/50-modern.css`；宣告檢查範例同步維護於 `scripts/preview-css/admin-navigation.json`，不影響公開網站或登入頁品牌區。

## 區塊間距基準

目前以「營業工作台」已確認的畫面作為間距基準：

- 垂直區塊間距：`18px`
- 左右並排區塊間距：`18px`
- CSS 變數：`--admin-space-block` 與 `--admin-space-inline`

兩者目前同為 `18px`，分開命名是為了未來若垂直與水平需要不同節奏時，可以只調整設計 token，不必逐頁搜尋固定數值。

## 使用方式

### 垂直堆疊

頁面主要區塊使用 grid 或 flex 的 `gap: var(--admin-space-block)`。例如工作台的指標、出勤卡、主要操作、工作內容與快速入口，都應維持單一 18px 間距。

### 左右並排

兩欄或多欄的功能面板使用 `column-gap: var(--admin-space-inline)`，通常可直接使用 `gap: var(--admin-space-inline)`。並排面板的水平間距沿用此規則；服務員工作台目前採垂直堆疊。

### 工作台視角切換列

所有帳號的 `.adminRoleSwitcher` 與下方角色工作台內容之間保留一個 `var(--admin-space-block)` 的垂直間距，包含開發者預覽；由切換列的單一 `margin-bottom` 控制，不再於開發者版本另加留白。切換按鈕保留既有緊湊間距，偏好規則使用 `AdminHelp`；文字按鈕樣式排除 `.adminHelpTrigger`，避免覆蓋共用小驚嘆號幾何與配色。

計薪職位欄位由 `AdminPayrollRoleField` 共用，標籤與說明圖示分開；`.adminFieldHeading` 沿用 6px 圖示間距、桌面至少 24px／觸控至少 44px 的標籤列。欄位、下拉選單、表單內部間距、字型與對話框底部按鈕沿用現有規格，不逐頁加字級覆寫。

### 避免間距疊加

同一層不要同時使用父層 `gap` 和子面板的 `margin-bottom` 來表達區塊間距。當面板放在 grid／flex 容器中時，子面板應使用 `margin-bottom: 0`，由父層 gap 統一控制。

一般文件流頁面若沒有父層 gap，才使用 `.adminPanel` 的 `margin-bottom: var(--admin-space-block)`。

## 服務員工作台指標卡片

採用「主指標放大」版型。桌機四張獨立卡片的寬度比例為 `2:1:1:1`，卡片間距沿用 `18px`；第一張「待處理訂單」為主要指標。

- 每張卡片只保留「主題、數量、說明」三個元素。左側顯示主題與說明，右側顯示數量。
- 主指標主題 `26px`、數量 `22px`、說明 `14px`；其餘卡片主題 `20px`、數量 `18px`、說明 `14px`。主題加粗並使用主要文字色，說明使用次要文字色。
- 所有卡片使用同樣 `14px 16px` 內距與至少 `112px` 高度，內容整組垂直置中。主題列至少 `36px`、說明列至少 `28px`，數量在右側跨兩列置中並靠右對齊；文字可以換行，不使用刪節號隱藏內容。
- 視窗寬度 `1200px` 以下改為等寬兩欄，`560px` 以下改為單欄；仍維持左側文字、右側數量及 `18px` 卡片間距。

此版型套用於 `.adminRoleDashboard-service`，其他角色工作台的指標維持各自既有版型。

## 營業工作台主要操作區

服務員工作台的主要操作依現場流程排列：

- 「發點餐碼」與「訂購包廂」並排放在頁首右上角，各自開啟既有建碼及包廂訂購抽屜，不另設操作卡。
- 出勤沿用指名人員的精簡橫向狀態列，顯示人員、營業狀態、打卡時間與上下班按鈕；服務員視角只呈現打卡控制。
- 「現場待辦」獨立佔滿一列，其下為現場快速入口；移除工作台內的包廂服務排程區塊，透過「管理包廂」進入完整排程。
- 現場快速入口的「完整訂單」「管理包廂」「查詢訂單」放在標題及說明右側並靠右對齊；窄版移至標題下方、靠右並允許換行，不另保留內容列。
- 區塊之間維持 `var(--admin-space-block)`。

所有後台頁面的一般重新整理控制統一使用 `features/admin/shared/AdminRefreshButton.tsx`，文字為「重整↻」，迴轉符號置於文字之後。超過 1020px 時將「重整、通知」由左至右並排於視窗右上角，間距 8px、頂部至少 20px、右側至少 24px，納入安全區；重整按鈕使用工具列內的自然排列，避免覆蓋頁首主要操作。1020px 以下採兩列頁首，第一列為品牌與 MENU，第二列依序為重整、通知與主題切換，展開的導覽列置於其下。第二列實際占用版面空間，通知與重整至少 48px 高；通知面板以所在工具列為定位基準，不被頁首裁切。所有寬度均透過 `AdminToolbarProvider` 的插槽呈現所在頁面的重整按鈕，載入或儲存期間依原頁面的停用條件處理，並保留資料更新回呼與草稿保護。錯誤重試與明確標示放棄修改的重新載入操作維持所在區塊，不另建立重疊的浮動按鈕。

重整與通知共用尺寸規則，以通知按鈕為準：繼承工具列字型、字重與行高，上下 10px／左右 14px 內距，桌面至少 42px 高、1020px 以下至少 48px 高。按鈕寬度依內容自然計算，未讀數增加時仍保留完整文字。

## 工作台短表單抽屜

- 「發點餐碼」與「訂購包廂」共用 `adminOrderPassDrawer` 版型，面板連同關閉按鈕向下避讓通知；桌面使用 `max(20px, safe-area-inset-top) + 56px`，1020px 以下避讓兩列工具列，使用 `max(10px, safe-area-inset-top) + 142px`。
- 遮罩仍覆蓋整個視窗，面板底部貼齊視窗底部，可用高度扣除頂部避讓空間。內容保留內部捲動及邊界捲動限制，適用較小高度、較多 UID 候選、已建碼資訊與表單錯誤訊息。
- 通知位置維持既有規則；此避讓限於工作台短表單抽屜，訂單查詢與留言板的 portal 抽屜維持各自既有配置。

## 窄版返回頁面頂端

- 1020px 以下的後台頁面共用右下角「↑ TOP」圓形懸浮按鈕，尺寸 62px，距離右側至少 14px、底部 14px 加安全區；配色沿用後台明暗主題。
- 窄版內容底部保留 90px 加安全區，讓頁尾操作捲動至底部時仍可完整顯示。
- 顯示門檻比照公開網站：捲動距離超過 260px 或視窗高度的 34%（取較小值）後出現，返回頂端後隱藏；桌機不顯示。
- 點擊平滑返回整頁頂端；減少動態效果偏好改為立即返回。按鈕提供「回到頁面頂端」的可讀名稱、鍵盤焦點與明確的焦點外框，層級低於通知提示和對話框。
- 實作集中於 `features/admin/shared/AdminBackToTop.tsx`，由後台 layout 統一掛載，各頁無須另外新增捲動監聽。

## 訂單查詢：清單優先與明細抽屜

- 查詢條件依序為營業日、關鍵字、訂單狀態；關鍵字占用剩餘寬度，手機改成單欄。
- 頁面標題 32px、說明 14px，查詢標籤 14px、輸入文字 16px。標頭操作預留右側浮動通知及重整按鈕空間。
- 清單占滿內容寬度，結果數放在清單標頭。欄名 14px、主要資料 16px、次要資料 13px，金額靠右。
- 未選訂單時不顯示空白明細面板。點擊資料列或以鍵盤啟用訂單編號後，開啟寬度最多 560px 的右側明細抽屜；小螢幕使用全寬。
- 抽屜使用既有 Base UI Dialog，提供焦點限制、Esc／遮罩關閉及返回原觸發按鈕；層級高於通知與重整按鈕。
- 此次保留既有 `AdminOrderListPage.jsx` 及 API 讀取流程，僅調整呈現與明細開關；資料契約型別化及 TSX 遷移留待獨立重構，避免 UI 迭代擴大至 API 契約變動。

## 完整點單管理：緊湊配置與帳款層次

- 頁面標題為「完整點單管理」。桌面左側顧客清單 280px，右側使用剩餘寬度，依序為顧客資訊、交付與查詢操作、訂單和現場帳款，區塊間距 18px。左側工具列與日期欄位允許縮至欄寬，營業時段以完整時間為單位換行，避免內容撐大後遭裁切。右側使用整頁捲動，避免雙重捲動容器。
- 顧客姓名 24px，狀態獨立標示；不重複顯示「目前顧客」。桌面姓名後方橫排遊戲 ID 與本營業日訂單數，兩者為 14px；窄版自然換行。餘額和消費摘要 18px。點餐管理標題 18px，欄內靠右對齊，右側接續指名人數欄位與操作；760px 以下改為標題在上、內容在下，內部留白 8–14px。
- 顧客卡片內分為「點餐管理」與「顧客服務」兩組操作。繪圖／簽繪建立交付、作品交付查詢及歷史訂單整合於卡片底部，以細分隔線與點餐操作區分；建立交付使用 secondary 按鈕，查詢使用 ghost 按鈕，所有入口沿用目前顧客與營業日參數。
- 顧客服務按鈕文案為「建立作品」、「查看作品」、「歷史訂單」，整組靠右；點餐操作使用「尋回點餐碼」與「重開點餐」，指名人數輸入數字置中。內部備註與狀態操作原因標籤均為 12px，與餐點分類標籤一致；狀態操作按鈕整組靠右並允許換行。
- 搜尋與餐點修改使用共用 secondary 按鈕，餐點刪除使用 danger；區塊舊樣式不覆蓋 AdminButton 的配色與停用提示。顧客服務按鈕容器清除既有上下 16px margin，與點餐管理沿用相同的 14px 分隔線內距及 40px 桌面控制項，窄版內容仍可自然換行。
- 左側工具列不隨顧客名單捲動；名單使用獨立可鍵盤操作的捲動區，桌面左欄高度上限依 viewport 計算，手機為 380px。捲軸沿用 `95-scrollbars.css` 的共用明暗主題與內縮留白。顧客列上下各 6px，至少 44px 高，長名稱與 ID 保留換行。
- 訂單品項使用品名、數量、金額、操作四欄；名稱和右側數量均為 16px。修改與刪除沿用 Lucide Pencil／Trash2，套用共用 iconActionButton 的 36px 桌面／44px 觸控規格，保留可讀名稱、展開狀態與停用條件。重新排程按鈕文案統一為「重新排程」，原狀態操作與原因要求保留。
- 訂單標頭只顯示一次主要狀態。下方僅呈現與主要狀態不同的排隊階段說明及大於零的分鐘數；沒有額外資訊時不保留空白說明列。
- 帳款標題 20px、項目標題 16px、說明 13px。待收／待退金額 26px，必要時標示「暫計」；「應收、實收、退款、淨收」摘要標籤 16px、金額 24px，480px 以下金額 20px。
- 登記說明與按鈕各自分區，款項紀錄區分種類、狀態、原因、時間與金額；沿用共用 AdminButton，桌面至少 40px 高、觸控至少 44px 高。長文字與金額可換行。
- 760px 以下顧客清單與詳情改為單欄，帳款主指標置於摘要上方；480px 以下表單單欄與顧客操作全寬。配色沿用明暗主題 token。
- 專屬樣式集中於 `styles/admin/layers/93-orders-workspace.css`。顧客標頭與訂單品項列抽為 TSX；既有大型 `AdminOrdersPage.jsx` 僅調整標題、組合和區段標籤，資料契約與其餘 JSX 的遷移留待獨立重構。

## 通知規則清單：清楚單列

- 左側為 36px 圖示底塊與 24px 圖示，中間為規則名稱及說明；文字區使用透明背景，不另加深色底塊。
- 名稱 16px、700 字重，說明 13px；兩者間距 5px。長名稱及說明允許換行，手機不縮小名稱字級。
- 右側將 12px 啟用狀態放在 44 × 24px 開關上方，間距 6px；尾端使用單一 16px 右箭頭進入編輯。選取區、開關和箭頭各自保留獨立操作及可讀名稱，不將開關嵌套於編輯按鈕。
- 藍色邊框與淡藍底色只表示目前選取；綠色狀態及開關表示啟用，灰色表示未啟用，並保留文字及 switch 語意。
- 清單間距 10px、列內距 12px、元素間距 12px；手機縮減水平間距，但不隱藏啟用狀態。觸控時編輯入口及開關有效點擊區至少 44px。
- 樣式集中於 `styles/admin/layers/70-notifications.css`，個人通知與店內廣播沿用同一個清單元件；儲存、權限及 API 行為不變。

## 通知規則編輯標頭

- 標頭依序顯示「編輯規則」、目前選取規則的名稱、啟用狀態及「規則 N/N」。規則名稱使用 20px、700 字重；位置資訊使用 16px、650 字重，維持次要但清晰的層級。
- 標頭名稱與左側清單使用相同來源：優先顯示目前草稿的 `rule.name`，未填名稱才顯示事件類型的預設名稱。透過既有「自訂規則名稱」欄位修改後即同步顯示，仍須按「儲存設定」才會保存。
- 標頭名稱維持純文字，沒有輸入欄位的背景、圓角及內距；名稱的編輯入口不移動，也不改變通知事件類型或資料契約。
- 規則名稱可以換行，位置資訊靠右且保持完整。600px 以下分成兩列：第一列為編輯標題及規則名稱，第二列為啟用狀態與規則位置；不縮小名稱及位置字級。
- 空清單保留「尚未選取」及原有空狀態。個人通知與店內廣播共用相同呈現，不改變規則資料或儲存流程。

## 後台捲軸：內嵌細捲軸

- 整頁、側欄、清單與抽屜使用同一組捲軸 token，樣式集中於 `styles/admin/layers/95-scrollbars.css`，只由後台入口匯入。
- Blink／WebKit 捲軸寬／高為 8px，滑塊為膠囊形，保留 1px 軌道色邊緣與 hover 提示；Firefox 使用原生 `thin`，不強制改寫平台原生外觀。
- 亮色軌道 `#e8edf2`、滑塊 `#8a99ac`、hover `#657b98`；暗色軌道 `#101a1e`、滑塊 `#526978`、hover `#829bb0`。高對比模式恢復系統色與較寬目標。
- 側欄外層保留原有圓角與邊框，以 `.adminTopbarScroll` 承接原有內容的捲動；桌面捲動區上下各內縮 12px、右側 6px，避免捲軸碰到圓角邊框。手機保留原本的導覽展開與 grid 排列。
- 右側仍使用整頁原生捲動，不新增主內容捲動容器。透過 `:root:has(.adminTheme)` 讓根層與後台內部使用相同配色；後台容器卸載後自動失效，即使儲存的 `data-admin-theme` 或 CSS 仍在，也不影響公開頁面。
- 新增後台捲動區直接沿用共用規格，不另定 scrollbar 顏色或寬度。鍵盤、滾輪、觸控與表單操作保持原有行為；實際樣式仍依瀏覽器與作業系統呈現。

## 不屬於本規範的間距

繪圖／簽繪交付使用個人工作台：上方範圍與搜尋、左側委託清單、右側固定詳情位置，區塊間距沿用 18px token。詳情分為作品內容、領取資料與處理紀錄，保留共用 44px 控制項、原生頁面捲動與既有展開箭頭；900px 以下改單欄。樣式集中於 `styles/admin/layers/92-delivery-workspace.css`，功能與本地驗證紀錄見 `art-delivery-workspace-implementation.md`。

通知中心的「放棄變更／儲存設定」作用於目前頁籤的整組規則，使用獨立設定列，放在範圍頁籤下方、左右規則工作區上方；不得放在單筆規則編輯器內。設定列顯示「我的通知設定／店內廣播設定」及未儲存狀態，保留原有停用、確認與儲存回呼。編輯器只保留單筆複製、移除和排序；音效上傳／刪除、本裝置權限及手動廣播維持各自操作，不納入規則儲存。

純圖示操作採用[全站圖示按鈕標準](icon-action-design-standard.md)：桌面按鈕 36px、圖示 24px、零內距置中，觸控點擊區為 44px。文字按鈕、開關及展開控制不混用。

通知設定的「自訂規則名稱」展開控制保留文字旁的 34px 圓形按鈕外觀，文字與圖示緊湊排列，不拉成整列；圓框內使用與方案一相同的單一 16px 箭頭並置中，展開時旋轉 180 度。整個標題區至少 44px 高，保留原生 `details/summary` 的鍵盤與展開語意，不將其視為選單或改動規則資料。此展開控制保留圓框以提升可操作辨識度，不套用原生下拉欄位的無框規則。

營運總覽的「帳號安全工具」、「頁面顯示狀態」及「使用者帳號列表」沿用同樣的 34px 圓框與 16px SVG 箭頭，靠右且水平／垂直置中；不使用文字字元或偏移補償定位。展開時只旋轉箭頭 180 度，hover／鍵盤焦點強調圓框。整個區塊標頭仍是原生 `summary` 的操作區，保留明暗主題、焦點與既有展開狀態；樣式集中於 `styles/admin/layers/80-controls.css`。

結算工作台的出勤修正、計薪輸入、分潤明細、薪資預覽、支付與更正差額，使用 `features/admin/shared/AdminDisclosureSummary.tsx` 沿用同一規範；個人帳目的出勤修正也由同一元件呈現。新增加的區塊展開標頭優先使用此元件，保留原生 `details/summary` 的開關行為，圓框與 SVG 樣式仍集中於 `80-controls.css`。

後台所有原生單選欄位使用[全站下拉選單設計標準](select-design-standard.md)：單一 16px 箭頭、右側 14px、垂直置中、至少 44px 高。樣式集中在 `styles/shared/select.css`，多選清單不套用。

- 面板內距，例如 `.adminPanel` 的 `padding`。
- 標題與說明文字之間的排版距離。
- 表單欄位、按鈕群組、清單列等元件內部的緊湊間距。
- 手機版改為單欄後的內容排序；單欄仍應保留 18px 的垂直區塊間距。

這些屬於元件自身的排版規則，除非造成整體區塊節奏不一致，否則不應直接套用頁面區塊間距。
