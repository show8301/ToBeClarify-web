# 繪圖／簽繪交付功能盤點與設計方向

日期：2026-10-10。保留使用者已確認的交付權限範圍，將問題定位為功能與工作流程缺口。

本次以使用者補充的 dev 交付清單／管理區截圖、目前 Web／API 程式碼及上一份權限稽核為依據。工具的瀏覽器存取檢查未能通過，沒有直接讀取即時 DOM；畫面配置已由補充截圖確認，動態操作仍未驗證。設計示意使用範例資料。

## 核心問題

「想重發」可能實際上是「想再次拿到同一組領取資料」。現有頁面只在建立或重發成功後顯示領取碼，重新整理、關閉或離開就無法查看；缺少日常使用的「檢視／再次複製領取資料」入口。

此外，目前只有全店清單、來源 session、搜尋與交付狀態。作品沒有負責人關聯，也沒有「我的委託」篩選。這是工作分配資料與查找方式的缺口；新增個人視圖不代表縮小現有全店存取權限。

補充截圖也確認：交付管理區在整份清單與分頁按鈕之後，選取作品後需要向下找到管理區；其中「重發單筆領取碼」位於表單上方，但沒有同位置的檢視／複製領取資料。資料表單、狀態、附件與交付操作需要更清楚的優先順序。

## 已有能力

- 從歷史顧客／訂單建立作品，設定名稱、顧客可見說明與交付日。
- 建立時產生單筆領取碼；本次回應可複製碼及單筆領取連結。
- 搜尋與狀態篩選，查看來源訂單。
- 上傳圖片、加入 HTTPS 雲端連結、檢視及移除附件。
- 手動設定待製作、製作中、可領取、已領取、已取消。
- 顧客以領取碼或 UID 查詢作品、下載附件、確認收到。
- 經理／開發者重發領取碼。

以下建議是在這些能力上補齊流程。

## 功能缺口

| 優先順序 | 功能缺口 | 現有實作與影響 | 建議 |
|---|---|---|---|
| 優先 | 再次檢視與複製領取資料 | 明碼只保留在當次頁面狀態；一般作品明細不回傳碼 | 每筆作品設「領取資料」區，區分檢視、複製及使舊碼失效的重發 |
| 優先 | 選取作品的上下文與操作優先順序 | 管理區在整份清單下方；重發位於表單頂部，日常交付動作缺少固定位置 | 桌面固定詳情區、手機獨立作品詳情；標題、階段與下一步先呈現，作品資料與附件分區 |
| 優先 | 我的委託與負責人 | DTO／查詢沒有負責人；不能準確判斷哪些作品由自己負責 | 加入作品負責人與協作關聯，預設「我負責」，保留「全部交付」切換；不以建立者直接推定作者 |
| 優先 | 下一步與開放領取流程 | 附件、狀態、交付碼散在同一長表單；靠手動狀態選單完成交付 | 按階段顯示下一步：準備作品、檢查顧客可見內容、開放領取、提供領取資料、確認收到 |
| 次優先 | 已通知／待通知追蹤 | `ready` 只表示開放附件，沒有通知欄位或通知紀錄 | 先提供可複製交付文字與人工「已告知」紀錄；之後有明確聯絡管道再做實際通知 |
| 次優先 | 到期、逾期、待領取排序 | 交付日只顯示文字；清單固定依建立時間排序 | 依交付日或更新時間排序，加入逾期／即將到期／已開放待領取篩選 |
| 次優先 | 顧客視角預覽 | 管理者只能檢視單個附件，沒有完整顧客版預覽 | 預覽顧客將看到的名稱、說明、檔案及狀態；草稿預覽留在後台，不提前公開 |
| 次優先 | 處理紀錄與收件來源 | API 有異動稽核寫入，但交付頁沒有讀取入口；已領取時間可能來自後台修改或顧客確認 | 呈現建立、更新、開放、碼重發、告知與收件紀錄，區分「顧客確認」與「店員代記」 |
| 次優先 | 未儲存內容保護 | 關閉／切換管理作品會離開編輯表單，沒有未儲存提醒 | 提醒儲存或放棄變更；敏感領取資料不存入瀏覽器持久草稿 |
| 後續 | 附件管理 | 單次一張圖片、附件逐筆加入／移除；修改附件自動回製作中 | 多檔上傳、排序、封面、清楚的換圖流程；若要更新時維持已發布版本，需要後端草稿／發布版本設計 |
| 後續 | 建立與來源核對 | 建立表單只提示日期及來源類型，需另外跳到訂單確認顧客 | 建立時直接呈現來源顧客、UID、訂單／項目摘要及負責人，減少跨頁核對 |
| 後續 | 操作回饋 | 複製失敗沒有可見訊息；部分受作品狀態限制的操作仍可按下後才遭 API 拒絕 | 顯示成功、失敗與停用原因；已關閉作品明確提供重新開啟的下一步 |

「下載／查看」與「顧客確認收到」仍應區分；不能把點開連結或按複製當成已領取，也不能把複製交付文字當成已通知。

逾期提示先用於交付日已過、仍待製作／製作中的作品；已開放或已領取的作品不能僅因交付日已過就顯示為製作逾期。已開放作品另外追蹤待告知／待確認。

## 領取資料需要先選定保存方式

資料庫目前保存 `CLAIM_CODE_HASH`，不保存可還原的領取碼。補一個按鈕無法取回舊碼。

| 方向 | 日常使用 | 舊作品處理 | 範圍 |
|---|---|---|---|
| 保留一次顯示，改善當次保存 | 建立後可下載／列印交付憑證，醒目提醒保存；關閉後仍不能再次取得單筆碼 | 未保存者仍走既有重發流程 | 功能較少，保留目前雜湊保存方式；無法完整解決再次查看需求 |
| 保存可再次讀取的單筆憑證（建議） | 後台可再次檢視／複製同一組領取碼，日常查閱不使舊碼失效；重發仍依現有權限 | 舊碼不能回推，需經既有重發流程建立新碼後才有可讀取資料 | 需要 API／資料保存調整，採可解密保存並記錄檢視；不只 Web 畫面調整 |

已歸戶顧客可以另提供 UID 領取連結，現有顧客頁已支援 `#uid=...`。但它能開啟該 UID 的已歸戶作品，不能視為單筆領取碼的替代版本；介面應分別標為「本件作品領取」與「顧客全部已歸戶作品」。未歸戶作品不能使用 UID 入口。

## 三種畫面方向

### 清單＋固定詳情

保留清單為主，桌面將選取作品的詳情放在右側，手機改為清單下方。作品標題、狀態、交付日和領取資料放在詳情頂部，附件與編輯內容置後。

- 適合：快速補齊目前缺失、維持熟悉的查找方式。
- 重點：再次查看領取資料、交付文字、到期排序、顧客預覽。
- 取捨：同時追蹤多件作品的進度仍依賴清單篩選；編輯內容需分區收合。

### 個人交付工作台（建議）

預設「我的委託」，可切換「全部交付」。左側為待辦作品，右側呈現所選作品的階段及下一步；詳情分成作品內容、領取資料、處理紀錄。個人視圖只改顯示範圍，保留現有全店操作權限。

- 適合：指名人員日常管理、同時處理多件委託。
- 重點：負責人資料、待製作／待開放／待告知／待確認的操作提醒，領取資料可以隨時回到固定位置。
- 取捨：需要先建立負責人關聯；歷史委託應列為「待分配」，由人員確認，不能用建立者自動推定。

### 交付進度看板

按待製作、製作中、可領取、已領取分欄；取消作品收進篩選／封存區。每張卡呈現負責人、交付日、逾期及通知資訊；選取後展開作品詳情。

- 適合：經理協調多人製作、辨識哪一個階段堆積。
- 重點：跨人員概覽、逾期作品、已開放但尚未告知／確認的作品。
- 取捨：大量已完成作品需要封存與搜尋；手機要堆疊各欄。首版使用明確操作確認進度，不必加入拖曳更新狀態。

## 建議實作順序

1. 先確定可再次檢視的單筆領取資料機制，補齊複製回饋；交付頁上保留獨立的重發入口與既有權限。
2. 建立負責人／協作欄位與舊作品分配方式，加入「我的委託」視圖與交付日排序。
3. 使用個人交付工作台組織下一步、顧客預覽、人工告知紀錄及處理歷程。
4. 需求增加時，再從相同資料提供全店看板、多檔管理與經使用者指定管道的實際通知。

本次僅盤點及提出設計；沒有變更 Web／API 功能或部署。
