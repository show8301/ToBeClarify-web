# 顧客 UID、歷史顧客與委託交付

本文件對應 2026-09-22 的實作。入口為 `/collection`；後台入口為 `/admin/customers` 與 `/admin/deliveries`。本階段已完成本機程式調整，migration、API 發布與 Web dev 發布另行執行。

## 顧客識別

| 資料 | 用途 | 可否領作品 |
|---|---|---|
| 遊戲 ID | 店員建立 session、歷史顧客搜尋、未驗證統計參考 | 否 |
| 當次 session／訂單 | 保留該營業日入場與消費關係、跳轉歷史訂單 | 否 |
| 當日找回碼 | 找回該次點餐資料的短期驗證碼 | 否 |
| 顧客 UID | 跨日歸戶、CRM 統計、UID 留言、UID 作品查詢 | 可查詢已歸戶作品 |
| 單筆領取碼 | 開啟一筆指定作品交付 | 僅該筆 |

UID 生成與歸戶以遊戲 ID 候選為前提：沒有候選建立新 UID，唯一候選沿用，多候選不自動合併；管理員可在開立點餐碼時選擇候選或稍後從歷史顧客頁核對。UID 不是登入帳號，也不是高強度身分驗證。

找回碼維持原本的某次入場 session 短期點餐恢復用途，不能用來領作品或發表圖片留言。系統不再發行、保存或驗證私密顧客憑證；舊資料欄位僅為資料庫相容性暫留。

## 店家流程

1. 後台開立點餐碼時輸入遊戲 ID。畫面顯示相同 ID 的 UID 候選；選擇既有 UID 需要管理員核對。沒有選擇時，唯一候選會自動沿用，多候選則保持待核對。
2. 從歷史顧客列表可依營業日、遊戲 ID、名稱、UID 或 session 查詢，查看訂單、作品交付與找回碼狀態，並跳轉到該次歷史訂單。
3. 對指定 session 建立繪圖／簽繪交付。每件作品產生獨立領取碼；建立後把領取碼或 `/collection#code=...` 連結交給顧客。
4. 作品完成後上傳圖片或加入 HTTPS 雲端連結，再將狀態設為 `ready`。顧客只在 `ready`／`delivered` 狀態看到附件；確認收件才會記錄 `delivered`。

交付狀態為 `pending`、`in_progress`、`ready`、`delivered`、`cancelled`。修改附件會回到製作中；領取碼重發只影響該筆作品。交付流程不改變原訂單付款、離場或結算。

## 顧客頁

`/collection` 提供兩種入口：單筆領取碼，或顧客 UID。UID 查詢只顯示已明確歸戶的作品；當日找回碼、遊戲 ID 與舊私密憑證都不是作品入口。圖片以授權 fetch 取得 Blob，不把秘密放在圖片 URL 或 query。

## 留言板

匿名文字留言維持可用。填寫 UID 可建立文字留言；附圖留言必須填寫有效 UID，沒有 UID 或 UID 無效時拒絕附圖。留言輸入不接受找回碼或舊版顧客私密憑證。公開留言卡片、回覆與單筆查詢都不回傳 UID，後台稽核仍可依資料庫關聯查找。

圖片大小、畫素、格式、重編碼、公開端點隱藏與限流沿用既有留言規則。UID 屬低強度持有式識別，功能搭配限流、內容審核與圖片限制使用。

## CRM 與統計

每日 session 與 `ORDERS.SESSION_ID` 是原始資料，不另複製單號主檔。以 UID 統計時只納入明確歸戶的 session；相同遊戲 ID 的未驗證群組只顯示參考次數與訂單金額，不視為同一顧客。正式消費榜仍需另訂退款、現金營業期、未歸戶與公開名稱規則。

## migration 與驗收

依序套用 `20260921_01_customer_commissions.sql`、`20260921_02_guestbook_identity_media.sql`、`20260922_01_customer_identity_uid_only.sql`。最後一支 migration 讓舊 `CREDENTIAL_HASH` 可為空，並加入找回碼發行時間／版本欄位；本次不自動連線資料庫或套用 migration。

本機已完成 API Release build 與 Web TypeScript 檢查。部署前需人工確認：首次／唯一／多候選 UID 歸戶、歷史顧客跳轉訂單、找回碼只恢復當日點餐、單筆領取碼隔離、UID 作品查詢、匿名留言、UID 圖片留言與公開 DTO 不洩漏 UID。
