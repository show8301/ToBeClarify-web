## 資料與操作邊界

- 實收與實退只反映已登記的現場金流，不以訂單應付推算。薪資及公司收入未正式結算前標示為試算。
- 未決帳款、款項歸屬、保留分潤及正式結算是否允許，維持 API 的既有規則。清單不額外要求所有保留款為零才可結算。
- 帳款由現有逐顧客端點讀取，每批至多四位顧客；營運設定及結算讀取獨立完成，不等待帳款整批載入。
- 日期、角色及刷新切換取消舊讀取；無法取得的帳款顯示錯誤，不計成零待辦。刷新期間不沿用舊的金額快照作為新結果。
- 舊版顧客帳款提示回到完整點單管理。跨期案件顯示原營業日，不加總逐顧客歷史現金作為本日實收。
- 營業期異動使用日期、版本及操作編號；不確定結果保留原請求供查回。廣播不確定結果保留原發送編號及鎖定草稿。
- 調班前核對既有班表內容，若已更新則停止；休假與提前下班沿用排班 API，打卡、工時及原服務紀錄不自動改寫。
- 營運控制的關店入口維持 API 授權與未完成訂單限制；薪資資料暫不可用時仍可由 API 執行關店檢核，不把薪資規則設定變成新增關店條件。

## 營運控制精簡調整

營運控制改為狀態卡；依後續畫面意見，桌機目前為等寬雙欄，左欄依序是營運控制、店內廣播與包廂服務，右欄是當班人力。兩欄均填滿欄寬，整列外緣與上下卡片對齊；1100px 以下上下排列，各卡片保留自然高度。

- 常駐只顯示狀態、日期、預計關店、適用的接單模式及新指名暫停狀態。
- 營業計畫、關店時間、暫停／解除新指名與接單模式確認均改用共用 dialog。操作原因只在需要填寫的確認視窗出現。
- 未開店顯示營業計畫／開店；已關店／已結算顯示安排下次營業；誤關重開收至更多操作。
- 營業計畫視窗最大 760px，操作確認視窗最大 520px，最大高度為 90dvh，沿用 dialog 內部捲動。
- 共用營業計畫新增僅供工作台 dialog 使用的 compact 呈現；省略重複標題與裝飾外框，營業日獨立一列，開始與結束時間雙欄，640px 以下單欄。完整點單管理保留原版型。
- 實際關店按鈕集中在收班清單的關店步驟，沿用既有未完成訂單／服務檢核與 API 版本、操作編號；背景同步不改寫已開啟確認視窗所核對的營業期版本。

本次為本地畫面迭代，未變更 API、資料庫、營業規則或權限，也未推送部署。

## 人力區獨立載入與停用說明

人力區透過 [staffingWorkspace.ts](../features/admin/operations/staffingWorkspace.ts) 自行讀取並驗證營業日、店員與班表；上層營運讀取保留訂單、包廂及角色用途，不再重複讀取班表。人力編輯結束只等待自身刷新，上層訂單等資料另行背景更新。切換帳號會取消舊請求並隔離先前資料；401／403 會重新確認登入狀態，已知權限失效仍限制操作。

停用說明由[人力輸入說明浮層](../features/admin/operations/StaffingAvailabilityHint.tsx)顯示於標籤右側。新建與編輯班次使用明確模式，新建不沿用原休假狀態。縮減班次需通過 [staffingSafety.ts](../features/admin/operations/staffingSafety.ts) 與 [staffingServices.ts](../features/admin/operations/staffingServices.ts) 的服務／預約核對；測試以 [staffing-safety.test.mjs](../tests/staffing-safety.test.mjs) 的純邏輯情境覆蓋休假預設、跨午夜、縮減時段、資料異常及既有預約邊界，未接入 dev 部署流程。

這些檢核未新增 API 或資料庫異動，也不是後端原子鎖；核對後的並行修改風險仍依既有 API 處理能力。未在正式資料執行排班或服務 mutation。
