# 店員補登已成交訂單

原顧客的「點餐管理」新增「補登已成交訂單」。不論關店但未結算或已正式結算，店員都可補登；不需要重開顧客點餐。

填實際交易時間、補登原因，加入現有品項、實際服務店員與包廂。畫面預設現行價格，必須核對或改為當時成交價格；服務與包廂另外填實際開始、結束時間。時間明確使用台灣時區，完成後全部直接記為已完成，不進現在的候位或服務排程。

可選同一顧客尚未歸屬的既有收款。補登不會自動再記一筆實收；若付款尚未登記，儲存後使用既有帳款功能登記。混合收款或仍待確認的紀錄先在帳款更正。若已有同額未歸屬加收應付或已補登過相同小費，API 會要求先核對，避免重複應收／計薪。

預覽逐項原成交價格、應收與信物折抵後再送出。網路結果未明時鎖住原輸入，以相同操作 UUID 查回或重試；成功但訂單清單讀取失敗時只重新讀取，不再次新增。API 另攔截同一時刻、相同內容的重複補登。

訂單展示實際發生、登記時間、原因與是否關聯既有收款。已正式結算的畫面保留原版金額並顯示待重新結算筆數，仍只有原有經理權限可以在最終步驟填原因建立新的結算版本。

本功能需要 API 的 `20261020_02_order_backfills.sql`，應先依 API 本機 DBA 換版流程套用，再發布相容 API，最後 Web dev。尚未部署前不以正式 API 驗證新增交易。
