# 整單指名服務操作

2026-10-28。本次與 API／migration 一起發布，Web 先進 dev，使用者確認後才推進 main。

完整點單管理及指名營業工作台共用 `OrderServiceActions`、`order-service-api` 與 `order-service-types`。瀏覽器呼叫同源 admin proxy，API 是代表權、時段衝突與交易的唯一判定來源。

- 「整單現在開始」：所有尚未開始的指名以伺服器同一時間開始，自動承接未接單部分，各人的購買分鐘與休息各自保留。
- 「整單按預約時間補登開始」：操作者確認每位確實已在畫面所列有效預約時間開始。時間不同選「改實際時間」；超過預計結束須明確選服務中或已完成及實際結束。
- 「整單承接」與「整單完成指名服務」同樣由任一名本單有效指名人員或經理代表執行。餐點、包廂及收款仍依各自流程處理。

各按鍵預先讀取 API 資格，每 15 秒、重新聚焦、父畫面資料更新或手動重讀刷新。POST 在鎖內重新核對；舊 snapshot 或新增衝突會拒絕整次操作。停用按鍵以 Base UI Popover 說明原因，支援 hover、鍵盤 focus 與觸控點擊，不使用 native disabled 按鍵作為唯一說明入口。

更正浮層保存開啟時的 targets 與 snapshot，避免背景更新悄悄改掉操作者核對範圍。未確認結果保留原 operationId／payload，同帳號重新載入面板可查回；結果不確定時不能另發新操作。這份暫存僅在頁面記憶體，登出清理，不存認證或顧客資料至瀏覽器儲存空間。

進階改期、跨期、取消、早完成及加購保留；移除這兩處各自複製的現在接待 preview。舊 API 路由仍留相容窗口，詳見 [API 契約、schema 與退場規劃](../../ToBeClarify-api/docs/order-service-flow.md)。

`AdminOrdersPage.jsx` 本次只刪除舊 V1 補登表單／逐人確認分支並接上 TSX 共用元件；其餘大型舊表單與資料狀態未重寫，避免把整頁型別遷移混入交易改動。新功能、契約、parser 均使用 strict TypeScript，後續實質重構該頁時再分段遷移。

本次只跑 build、型別、lint、部署與 HTTP 可用性檢查，依規範不跑 dev 自動化測試或瀏覽器測試。實際版面、鍵盤／觸控浮層與服務情境由使用者在測試站驗證。
