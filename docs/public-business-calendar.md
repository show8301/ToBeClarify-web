# 公開營業與值班行事曆

`/liveupdate` 的今夜時序與包廂狀態之間提供月份行事曆。日期採台北時間，班次依營業日分組；這是預定班表，不作為實際出勤或可接單判斷。

## 資料契約

瀏覽器透過同源 `GET /api/business-calendar?month=YYYY-MM` 查詢，Web 轉接 API 的 `GET /api/client/business-calendar`。省略月份時由 API 的台北日期決定當月。單次只回傳一個月份，允許年份 1900–9998，沒有逐日請求。

回應包含 `month`、`today` 與該月份每一天的 `days`。日期包含 `businessDate`、`status`、可空的 `startsAt`／`endsAt` 及 `staff`。店員只包含公開 ID、顯示名稱、頭像及班次起訖時間；不提供計薪職位、內部備註、審核人或休假紀錄。

| 狀態 | 來源及文案 |
| --- | --- |
| `unannounced` | 沒有營業計畫或紀錄，顯示「尚未公告」 |
| `planned` | 已儲存營業計畫、尚無實際營業紀錄，顯示「預計營業」 |
| `open` | 實際營業紀錄為 open，顯示「營業中」 |
| `operated` | 其他已有實際營業紀錄的日期，顯示「曾營業」 |

沒有常態開店假設，也沒有新增休店狀態。不得用預設營業時間、缺少排班或缺少資料推算休店。有班表但尚無營業安排時仍顯示已公開的班表。

營業資料來自既有 `BUSINESS_DAY_PLANS` 與 `BUSINESS_PERIODS`，實際營業紀錄優先。開始採實際開店時間（舊資料回退原開始時間）；結束採實際關店、預計關店、原結束時間依序回退。班次只取 `approved`、`IS_WORKING = TRUE`，店員可見性沿用公開名單的 `IS_ACTIVE = TRUE`。不變更資料表或現有審核流程。

## 畫面與更新

月份格提供前後月、回本月與日期選取；桌面顯示營業時間及前兩位店員，手機保留狀態與人數，完整時段及姓名在日期詳情顯示。跨午夜以「翌日」顯示並歸原營業日。

每 60 秒重新讀取，切換月份及卸載時取消請求與計時器。查詢失敗顯示錯誤與重試，不轉成休店或模擬成功。API 與 Web 回應均不快取。讀取的歷史班表是現存規劃，不是完整修改歷程，店員名稱也沿用目前公開資料。

## 驗證與發布

Web 執行 build、typecheck、lint；API 執行 build。API 的公開端點需先可用，Web 才能顯示真實行事曆。後續若發布測試環境，API 依正常流程至 main、Web 至 dev；正式 Web 仍須使用者確認後走 dev → main。此功能沒有 migration。依專案政策，dev 發布預設不執行自動化測試套件。

2026-11-16 本地結果：Web production build、TypeScript 與受影響檔案 lint 通過（保留既有原生圖片用法的效能提示）；API .NET 10 建置通過。本地唯讀預覽只註冊行事曆讀取服務，不啟動維護背景工作，3001 Web 代理成功讀取真實資料。HTTP 核對 2024-02 為 29 天、2026-12 與 2027-01 為 31 天，2026-13 回傳 400；匿名管理代理回傳 401。

CSS parser 核對七欄格線、桌面與手機日期格及手機隱藏細節規則均通過；Geist、Geist Mono、Noto Sans TC 的變數與 font-face 已輸出，抽查各字型資源為 HTTP 200。未操作瀏覽器，Computed／Rendered Fonts 與實際桌機／手機排版尚未確認。尚未部署 Web 或 API。
