# 公共小費按工時分配

本規則取代 [先前小費流程](order-tip-flow.md) 的人頭均分。

後台「補登已成交訂單」的小費提供公共小費（按工時分配）、指定店員、自訂比例。公共小費不在訂單鎖定人頭名單；訂單建立應收，帳款另外登記實收。一般顧客／代客訂單的指定部分維持指定小費，其餘為公共小費，畫面文字與 API 新快照同步。

原訂單的「訂單小費分配 → 更正此筆分配」可改變歸屬，需要原因並保留版本；不改應收或收退款。舊人頭均分與舊店家分配可辨識、更正，歷史資訊不自動改寫。

結算工作臺「金額核對」的公共小費改為唯讀訂單彙總，顯示本單應收、認列實收、小費認列金額及未全額認列原因。舊店家小費另列核對清單，不混入公共小費池。已正式結算時，此處標示目前來源，個人薪資仍以原版本為準，需經理預覽及填原因重新結算。

公共小費依指名人員、服務員、經理主要職位的計薪工時分配；幕後職位不參與。整數尾差依固定規則處理，個人合計與每張來源訂單都能對帳。個人薪資的公共小費欄可展開逐單來源；標籤中的工時及金額來自結算快照，不用現有出勤還原舊版。

舊手動公共小費仍顯示原值，需核對來源訂單與實收並填「舊手動公共小費核對原因」，再保存／重新結算，不能直接忽略或與新訂單重複相加。畫面不再提供手動金額欄位，請求 publicTipAmount 固定為 0。

本次沿用共用 Admin 控制項與既有樣式，不新增 CSS。兩份原有大型 JSX（OrderClient、AdminAssistedOrderPanel）只調整小費文案，未擴大改寫其狀態管理；新增邏輯維持 TS/TSX。

驗證入口：`node --test tests/settlement-public-tips.test.mjs tests/settlement-role-refresh.test.mjs`，包含新 API 來源資料驗證、伺服器元件靜態輸出、舊手動值提示、不可用狀態及出勤刷新。靜態輸出檢查不等同真實瀏覽器樣式／字型驗收；另執行 TypeScript、受影響 TS/TSX lint 及 production build。

10/18 五筆共 280 萬 G 的原店家小費需發布後透過既有訂單更正流程轉為公共小費，再由經理確認新版結算；本次程式與驗證不直接修改正式帳款。沿用既有 JSON 與來源快照表，不需要新的 migration。
