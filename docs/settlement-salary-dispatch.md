# 結算工作台：薪資派發

## 功能

分頁順序為「營運結算 → 個人帳目 → 薪資派發 → 結算設定」。
經理與開發者可進入薪資派發，一般店員不能進入，API 也強制檢查權限。

- 沿用頁面營業日期、時段及網址參數，`tab=dispatch` 可直接定位新分頁。
- 只在進入新分頁時載入派發清單，不加入一般店員的結算請求。
- API 合併每人的收入項目，Web 只呈現應發薪資、已給／未給、最後登記者與時間。
- 顯示已給、未給與總人數；手機使用雙欄緊湊列表，樣式沿用後台主題變數。
- 按「標記已給／改回未給」先確認，再保存；未正式結算不能登記。
- 更新期間鎖定重複操作及日期、時段、分頁切換；離開或登出清理請求。
- 更新成功或失敗後都讀回最新狀態，防止逾時已保存卻被盲目重送。
  讀回失敗時停用列表操作，要求重新載入。

這只是人工標記，不會轉帳、不會記錄實際支付金額，與原有支付／追回紀錄互不連動。
**重新結算後標記維持原樣，畫面呈現最新正式薪資，不自動核對差額。**

## 實作與發布

- `features/admin/settlement/SettlementSalaryDispatch.tsx`：獨立 UI、載入與確認操作。
- `salary-dispatch-types.ts`／`salary-dispatch-api.ts`：具名契約、執行期驗證，
  沿用共用 `adminRequest` 與同源 `/api/admin/...` proxy。
- 沿用 `AdminPanel`、`AdminDialog`、`AdminButton`；日期時間明確顯示台北時區。
- 使用 API 的結算版本與個人版本處理並行操作，不從瀏覽器推算薪資或權限。

需先套用 API 專案的 `20261024_01_settlement_salary_dispatch.sql`，再部署 API；
前置及驗收方向見 API 專案 `docs/settlement-salary-dispatch.md`。
API 無獨立測試主機，不應在未確認前自動套用正式 DB 或部署 main。
Web 仍先進 dev，待使用者確認後才以 dev → main PR 推進。

驗收包含桌機／手機、明暗模式、鍵盤分頁／對話框操作，以及後端拒絕過期版本後的讀回。
自動化套件不加入 dev 部署預設流程；依 AGENTS.md 執行建置、型別及 lint。
