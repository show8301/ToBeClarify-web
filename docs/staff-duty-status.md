# 店員執勤狀態

執勤狀態以 API 為唯一判斷來源：有已核准的上班時段，而且台灣時間現在位於該時段內，才算執勤。其餘為未執勤。班表開始時間包含在內，結束時間不包含在內，跨午夜仍歸原營業日。

## 操作方式

- 在「值班規劃」建立或調整日期、起訖時間與職位，核准後生效。
- 請假改為休假／不值班；提前下班調整結束時間，依既有權限完成核准。
- 「編輯店員」保留個人資料、服務與長期「開放指名」設定；當班接單與職位不再於此編輯。
- 店員在「營業工作台 → 我的當班狀態」操作「接受新指名」與「目前支援工作」；經理在「經理工作台 → 當班人力」展開個別店員操作。開關立即儲存，並顯示營業日、核准班次與唯讀的本班計薪職位。
- 「接受新指名」與「開放指名」獨立於執勤判斷；暫停接單不取消既有預約，也不等於提前下班。Web 送出單項接單或支援調整及營業日；API 在交易內讀取並鎖定最新班表與每日狀態，保留未調整欄位。實際打卡仍使用出勤 API。
- 「值班規劃」與「加入臨時排班」分別保存單選的 `payrollRole` 及可複選的預排支援 `scheduledRoles`。員工提報後須經理核准；經理儲存即核准。既有班表不可更換店員或營業日，應另建規劃。經理計薪職位僅適用於綁定經理／開發者帳號的人員。
- 「目前支援工作」使用 `activeRoles`，可在核准班次時段內依 `allowedSupportRoles` 調整，不受預排支援清單或計薪職位限制；指名支援須具備長期開放指名資格。支援影響依職位廣播受眾，不修改計薪、打卡或帳號權限。重新儲存／核准上班班表保留既有支援設定，休假清空支援。
- 工作台依帳號開放：店員可切換服務員／指名兩種，經理／開發者可切換三種。偏好保存在帳號，跨日、重新登入與換裝置沿用。網址 `workbench` 參數只指定本次視角；切換工作台不修改支援、接單或薪資職位。未排班仍可查看本人資料，實際新指名沿用核准班次與資格檢查。
- 本次先保存計薪職位，不改結算引擎；既有結算仍讀取原班表角色及結算輸入。計薪欄位接入結算及跨職位所得核對屬下一階段，不能將此階段稱為已完成單職位薪資計算。詳見[第一、二階段實作紀錄](workbench-preferences-support-implementation-20261017.md)。

本次新增工作狀態元件、回應驗證及契約均使用 TypeScript／TSX；既有 `AdminStaffSettingsPage.jsx` 僅移除營運區塊、對應處理函式及更新導引，為避免擴大到照片、服務與相簿編輯型別改寫，保留 JSX，後續實質改寫這些流程時再遷移。

### 經理當班人力清單

- 清單以工作台營業日的已核准上班班表為依據，保留尚未到班、執勤中及班次已結束的人員；其他日期仍在執勤的班次另標示「跨日執勤」。未排班、待核准、已退回及休假不列入正常清單，不以每日職位預設值判斷是否排班。
- 標頭、營業日、人數、搜尋新增與值班規劃入口位於捲動區外，只有員工列捲動。桌機清單最高為 `min(560px, 60vh)`，640px 以下最高為 `min(480px, 55dvh)`；每次只展開一個班次，定時重新讀取資料時保留捲動位置、搜尋及臨時排班草稿。
- 「加入臨時排班」以可輸入文字的下拉選單搜尋既有店員，只提供未列入清單的人員；選取後必須確認營業日、時段與職位，經理儲存即核准。已有待核准、退回、休假或時段不完整的紀錄時更新原班表，不另建同日重複班表。公開卡片隱藏不等於未排班，已核准的隱藏店員仍保留在清單並提示公開狀態。
- 核准班次展開後可使用「調班／休假／提前下班」修改原紀錄；提前下班調整結束時間，休假關閉本日值班。修改前核對班表內容；原打卡與已成立服務不自動改寫，需另外核對。整合範圍見[經理工作台](manager-workbench-20261016.md)。
- 人力區獨立讀取營業日、店員與班表；訂單、包廂或結算的讀取錯誤不連帶禁止搜尋。登入／權限、人力來源錯誤或營業日不完整仍禁止操作，並可使用「重新讀取人力」。背景刷新不取消尚未完成的同一筆人力讀取，返回分頁時亦同步。
- 「加入臨時排班」標籤右側 ⓘ 可由滑鼠停留、鍵盤聚焦或觸控點擊開啟說明。停用時說明實際原因；輸入框以 `aria-describedby` 關聯文字，圖示不跟隨輸入框停用。
- 新增臨時排班一律預設值班，包含原本休假的店員；新增視窗不提供休假開關。由核准名單開啟「修改」才沿用原值班狀態。
- 休假、延後開始或提早結束等縮減班次操作，會以原班次範圍讀取未快取的服務／預約，並在儲存前重讀；無法確認或會排除既有服務時停止送出。既有服務與跨營業期忙碌時段由現有 `/api/live-status` 的預約來源取得。延長班次、調整職位與新增臨時排班不依賴這筆讀取。
- 上述服務及班表核對是 Web 送出前的檢核；既有排班 API 未新增原子版本條件，因此不能宣稱已消除核對後到儲存瞬間的並行修改風險。API 授權、交易、打卡及已成立服務規則維持原狀。
- 儲存前重新確認目前營業日及既有班表版本；期間若被修改或已核准，不覆蓋新資料。結果不確定時先刷新、提示重新選取，不自動重送。新班次依既有 API 啟用核准職位，原本停止新指名的設定繼續保留。
- 未排班本身不再產生「需要經理介入」提醒；有進行中指名訂單卻未執勤的人員保留異常提醒，導向值班規劃確認。尚未到服務時間的未來預約不據此標成異常。

## 資料與相容性

- 保留 `isWorkingToday` 回應欄位以相容既有 Web，但其語意統一為「目前執勤」。
- 公開頁、後台與新指名的核准時段檢查共用 API 的 `StaffDutySql.IsOnDuty`。新指名檢查預約開始時間，允許在到班前預約班內時段。
- 舊排班、每日工作狀態與營業流程版本不再覆蓋核准班表。2026-10-17 的帳號偏好／計薪欄位需先執行相鄰 API 專案的 `db/migrations/20261017_01_workbench_preferences_payroll_role.sql`；不刪除舊角色資料或重算歷史結算。
- 目前執勤優先採涵蓋當下的核准班表，不受尚未關閉的其他日期營業期影響；指定日期的點餐目錄仍維持該日範圍。
- 舊 `/status` 寫入 `isWorkingToday` 的請求會被拒絕，應改至值班規劃調整。職位更新不再送出 `isWorking`。
- 店員卡片及個人頁透過同源 `GET /api/staff/status` 取得狀態，進頁面、返回分頁及每 60 秒同步。介紹與照片仍沿用既有快取，快照不作為公開卡片的執勤依據。
- 同步失敗顯示「狀態暫無法確認」，不沿用舊快照宣告待命。即時動態頁沿用自己的 60 秒同步，首次同步前與同步失敗時也不以快照列出執勤人員。
- 後台店員列表顯示「執勤中／未執勤」，另列核准時段，未執勤不再被一律標示成休假。

## 人工驗收情境

以下是驗收清單，不代表已在正式資料上執行。

| 情境 | 預期 |
| --- | --- |
| 沒有班表、待核准、已退回、核准休假或時間不完整 | 未執勤 |
| 核准 20:00～02:00，當日 19:59 | 未執勤 |
| 同一班表，20:00 起至翌日 01:59 | 執勤中 |
| 同一班表，翌日 02:00 起 | 未執勤 |
| 核准班內，但營業期仍指向另一日期 | 仍依涵蓋當下的核准班表判為執勤 |
| 核准班內但舊每日工作狀態為不上班 | 仍依核准班表判為執勤 |
| 舊排班標記上班但沒有核准班表 | 未執勤 |
| 班內有有效預約／忙碌區塊 | 執勤中，顯示指名中 |
| 停止承接新指名 | 執勤判斷不變，新指名被拒絕 |
| 在工作台關閉「接受新指名」後重新整理 | 保留暫停狀態，既有預約不變；經理當班人力同步顯示暫停 |
| 在兩種工作台視角間切換 | 本班啟用職位與接單狀態不變 |
| 在目前支援工作關閉一項職位 | 只改支援與職位廣播受眾，計薪、預排支援、執勤與帳號權限不變 |
| 核准班內啟用未預排但符合資格的支援工作 | 可操作，不修改計薪職位 |
| 在核准時段外調整支援，或啟用未具資格的指名支援 | API 拒絕並顯示原因 |
| 操作前 API 回傳營業日已變更 | 不送出修改，刷新後讓使用者確認新日期 |
| 工作狀態缺欄或 API 無法讀取 | 不可操作，不以預設值宣告可接單 |
| 經理當班人力有大量核准班次 | 員工列獨立捲動，標題、日期、人數與新增入口不隨清單移動 |
| 尚未到班、班次結束、待核准、休假與未排班同時存在 | 前兩者留在核准清單；後三者可搜尋加入，且不直接視為執勤 |
| 搜尋選到已有待核准／退回／休假班表的店員 | 提示修改原班表，確認時段與職位後才儲存核准 |
| 開啟臨時排班表單後發生定時刷新或營業日切換 | 草稿保留，儲存前重新核對日期；日期變更時停止送出 |
| 開啟表單後其他人先修改或核准同一班表 | 停止送出並提示確認最新班表，不覆蓋其他修改 |
| 非本營業日的跨午夜核准班次仍在執勤 | 清單保留並標示原營業日，不從當班人力消失 |
| 未排班店員沒有進行中指名訂單 | 不因「未執勤」產生經理異常提醒 |
| 編輯店員時尚有未儲存個人資料 | 視窗內不再有即時儲存當班狀態的開關，避免覆蓋表單 |
| 到班前預約核准班內的未來開始時間 | 通過班表資格檢查，其他交易驗證仍須通過 |
| 停在店員頁跨過班表邊界 | 下一次同步後更新狀態 |
| 狀態 API 失敗 | 顯示無法確認，不顯示待命或可以指名 |

API 契約細節見相鄰 API 專案的 `docs/API-DEVELOPMENT-GUIDE.md` 第 7.1、8.3 節。
