# 店員執勤狀態

執勤狀態以 API 為唯一判斷來源：有已核准的上班時段，而且台灣時間現在位於該時段內，才算執勤。其餘為未執勤。班表開始時間包含在內，結束時間不包含在內，跨午夜仍歸原營業日。

## 操作方式

- 在「值班規劃」建立或調整日期、起訖時間與職位，核准後生效。
- 請假改為休假／不值班；提前下班調整結束時間，依既有權限完成核准。
- 「開放指名」與「停止承接新指名」獨立於執勤判斷，既有預約不因停止接單自動取消。
- 今日職位開關只調整工作台身分，不決定是否執勤。實際打卡、工時及結算繼續使用既有出勤紀錄。

## 資料與相容性

- 保留 `isWorkingToday` 回應欄位以相容既有 Web，但其語意統一為「目前執勤」。
- 公開頁、後台與新指名的核准時段檢查共用 API 的 `StaffDutySql.IsOnDuty`。新指名檢查預約開始時間，允許在到班前預約班內時段。
- 舊排班、每日工作狀態與營業流程版本不再覆蓋核准班表。既有資料不刪除，不需要資料庫 migration。
- 目前執勤優先採涵蓋當下的核准班表，不受尚未關閉的其他日期營業期影響；指定日期的點餐目錄仍維持該日範圍。
- 舊 `/status` 寫入 `isWorkingToday` 的請求會被拒絕，應改至值班規劃調整。職位更新不再送出 `isWorking`。
- 店員卡片及個人頁透過同源 `GET /api/staff/status` 取得狀態，進頁面、返回分頁及每 60 秒同步。介紹與照片仍沿用既有快取，快照不作為公開卡片的執勤依據。
- 同步失敗顯示「狀態暫無法確認」，不沿用舊快照宣告待命。即時動態頁沿用自己的 60 秒同步，首次同步前與同步失敗時也不以快照列出執勤人員。
- 後台店員列表顯示「執勤中／未執勤」，另列核准時段，未執勤不再被一律標示成休假。

## 人工驗收情境

以下是驗收清單，不代表已在正式資料上執行。

| 情境 | 預期 |
| --- | --- |
| 沒有班表、待核准、已退回、核准休假或時間不完整 | 未執勤 |
| 核准 20:00～02:00，當日 19:59 | 未執勤 |
| 同一班表，20:00 起至翌日 01:59 | 執勤中 |
| 同一班表，翌日 02:00 起 | 未執勤 |
| 核准班內，但營業期仍指向另一日期 | 仍依涵蓋當下的核准班表判為執勤 |
| 核准班內但舊每日工作狀態為不上班 | 仍依核准班表判為執勤 |
| 舊排班標記上班但沒有核准班表 | 未執勤 |
| 班內有有效預約／忙碌區塊 | 執勤中，顯示指名中 |
| 停止承接新指名 | 執勤判斷不變，新指名被拒絕 |
| 到班前預約核准班內的未來開始時間 | 通過班表資格檢查，其他交易驗證仍須通過 |
| 停在店員頁跨過班表邊界 | 下一次同步後更新狀態 |
| 狀態 API 失敗 | 顯示無法確認，不顯示待命或可以指名 |

API 契約細節見相鄰 API 專案的 `docs/API-DEVELOPMENT-GUIDE.md` 第 7.1、8.3 節。
